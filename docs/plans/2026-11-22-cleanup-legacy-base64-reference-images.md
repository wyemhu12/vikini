## Technical Plan

### 1. Mục Tiêu (Goal) & Out of Scope (What We're NOT Doing)

#### Mục Tiêu (Goal)

Sau khi tính năng **Reference Images 40 MB Direct Upload** (`referenceImagePaths` qua `POST /api/generate-image/reference-upload-url` + Supabase Storage + Gemini Files API) đã đi vào vận hành (`docs/CHANGELOG.md:11-18`), dọn dẹp triệt để toàn bộ mã nguồn chế độ cũ truyền ảnh tham chiếu bằng chuỗi Base64 (`referenceImage` / `referenceImages`) trong JSON body của `POST /api/generate-image`:

1. **Chuyển đổi caller hoạt động cuối cùng (`requestImageVariation`)**: Chuyển `requestImageVariation` trong `src/lib/features/image-gen/studioHelpers.ts:340-369` từ `fileToBase64(blob)` + `options.referenceImage` sang bọc `Blob` thành `File` (chuẩn hóa MIME về 4 định dạng hợp lệ `image/png`, `image/jpeg`, `image/webp`, `image/gif`, kèm kiểm tra kích thước `0 < size <= 40 MB` và map lỗi quá `40MB` trong `classifyStudioError` tại `src/lib/features/image-gen/studioHelpers.ts:11-46` về khóa song ngữ có sẵn `studioRefFileTooLarge`) ➔ `uploadReferenceImages([file], params.conversationId, "Variation failed")` ➔ gửi `options.referenceImagePaths` tới `POST /api/generate-image`. Loại bỏ hoàn toàn nguy cơ lỗi Vercel `413 FUNCTION_PAYLOAD_TOO_LARGE` khi tạo biến thể từ ảnh 4K (> 3.3 MB).
2. **Xóa sạch dead code 0 active callers**: Xóa `convertReferenceImagesToBase64` (`src/lib/features/image-gen/studioHelpers.ts:310-324`), `fileToBase64` (`src/lib/features/image-gen/studioHelpers.ts:146-153`), tham số `referenceImagesBase64` và nhánh `options.referenceImages` trong `buildGenerateImageBody` (`src/lib/features/image-gen/studioHelpers.ts:117,130-133`).
3. **Thu gọn hợp đồng Type, API Route và AI Provider**:
   - Xóa `referenceImage?: string` và `referenceImages?: string[]` khỏi `ImageGenOptions` (`src/lib/features/image-gen/core/types.ts:54-55`, tự động phản chiếu qua facade `src/types/image-gen.ts:4-9`).
   - Xóa `referenceImage` / `referenceImages` khỏi `imageGenOptionsSchema` (`src/app/api/generate-image/route.ts:54-55`), đơn giản hóa nhánh auto-route `gemini-native` (`src/app/api/generate-image/route.ts:236-243`) chỉ kiểm tra `validatedRefPaths.length > 0`, và đơn giản hóa `savedOptions` / `referenceImageCount` ở Bước 5 (`src/app/api/generate-image/route.ts:360-382`) để chỉ destructure `referenceImagePaths: _referenceImagePaths` và gán `referenceImageCount = validatedRefPaths.length`.
   - Xóa hoàn toàn nhánh fallback base64 `referenceImageSources` trong `GeminiNativeImageProvider.generate` (`src/lib/features/image-gen/providers/GeminiNativeImageProvider.ts:78,82-83,118-132`), chỉ giữ `resolvedReferenceImages` (`inlineData` `<= 15 MB` hoặc Gemini Files API `> 15 MB`) và nhánh text-only.
4. **Cập nhật bộ test co-located theo Spec mới (Approved Spec Change — Loại C)** và ghi nhận vào `docs/CHANGELOG.md`.

### 3. Assumptions & Cross-Task Dependencies

#### Các giả định đã xác minh bằng `[SRC]`

1. **Zod v4 `z.object()` mặc định strip unknown keys** (`[SRC]` `node_modules/zod/v4/classic/schemas.js:575-582`, `node_modules/zod/v4/core/schemas.js:806-824,845-895,922-925`): Khi xóa `referenceImage` và `referenceImages` khỏi `imageGenOptionsSchema` (`src/app/api/generate-image/route.ts:54-55`) mà giữ `z.object(...)` (không dùng `z.strictObject()` / `.strict()` vốn đã deprecated cho `.strict()` trong Zod v4), mọi request từ tab trình duyệt cũ vô tình còn gửi `options.referenceImage` hoặc `options.referenceImages` sẽ **tự động bị strip** ngay ở `imageGenRequestSchema.parse(rawBody)` (`src/app/api/generate-image/route.ts:97`) — không làm sập client bằng HTTP 400 bất ngờ và bảo đảm payload base64 **không bao giờ** lọt xuống `provider.generate(...)` hay `saveMessage(...)`.
2. **Chỉ có đúng 3 Image Provider trong `ImageGenFactory`** (`[SRC]` `src/lib/features/image-gen/core/ImageGenFactory.ts:1-30`): `GeminiNativeImageProvider`, `ReplicateImageProvider`, `OpenAIImageProvider`. Cả `OpenAIImageProvider` (`src/lib/features/image-gen/providers/OpenAIImageProvider.ts:10-84`) lẫn `ReplicateImageProvider` (`src/lib/features/image-gen/providers/ReplicateImageProvider.ts:11-65`) đều **0 tham chiếu** tới `referenceImage` / `referenceImages` / `referenceImagePaths` / `resolvedReferenceImages`.
3. **`src/types/image-gen.ts` là facade re-export duy nhất** (`[SRC]` `src/types/image-gen.ts:4-9`, lịch sử bài học tại `docs/lessons-learned.md:35-40`): Xóa 2 trường khỏi `src/lib/features/image-gen/core/types.ts:54-55` tự động đồng bộ toàn bộ consumer import từ `@/types/image-gen` hoặc `@/lib/features/image-gen/core/types`.
4. **Client bundle hygiene cho `src/lib/features/image-gen/studioHelpers.ts`**: `src/lib/features/image-gen/studioHelpers.ts` được import bởi các `"use client"` hooks (`src/app/features/image-gen/components/hooks/useImageStudioActions.ts:5-18`, `src/app/features/chat/components/hooks/useImageGenController.ts:6`, `src/app/features/image-gen/components/EditPanel.tsx:9`). Do đó `requestImageVariation` chỉ import hằng số `STUDIO_REF_IMAGE_MAX_BYTES` (`1` dòng `85` ký tự) từ module lá client-safe `src/lib/features/files/uploadPresentation.ts:16` (giống `src/app/features/image-gen/components/ControlPanelReferenceImages.tsx:10-15`), **không** import `src/lib/features/image-gen/referenceImageStorage.ts` (vốn dùng `Buffer` và `@supabase/supabase-js` phía server), đồng thời khóa đồng bộ 1:1 giữa `VARIATION_MIME_EXT` và 4 MIME trong `STUDIO_REF_ALLOWED_MIME_TYPES` (`src/lib/features/files/uploadPresentation.ts:17-22`) qua bộ test `TC-CLEAN-01`.
5. **Xác thực magic bytes thực tế vẫn do server quyết định**: `POST /api/generate-image/reference-upload-url` chỉ nhận 4 MIME trong `ALLOWED_REF_IMAGE_MIME_TYPES` (`src/app/api/generate-image/reference-upload-url/route.ts:24`, `src/lib/features/image-gen/referenceImageStorage.ts:12-17`). Sau khi client tải lên qua Signed Upload URL, `downloadReferenceImagesFromStorage` (`src/lib/features/image-gen/referenceImageStorage.ts:186-207`) kiểm tra `data.size <= 40 MB` trước `arrayBuffer()` và phát hiện MIME thật bằng magic bytes (`detectImageMimeFromBytes`), đồng thời `finally` trong `src/app/api/generate-image/route.ts:473-482` luôn dọn file tạm `ref-<uuid>.<ext>`.
6. **Không đổi chữ ký công khai của `requestImageVariation` & phản hồi lỗi 40 MB song ngữ**: `src/app/features/image-gen/components/hooks/useImageStudioActions.ts:261-267` gọi `requestImageVariation({ imageUrl, originalPrompt, conversationId, model, aspectRatio })` và bắt mọi `Error` (gồm cả `ReferenceImageUploadError extends Error` tại `src/lib/features/image-gen/studioHelpers.ts:235-240`) để `logger.error("Variation Error:", error)` + `setShowError(classifyStudioError(...))` (`src/app/features/image-gen/components/hooks/useImageStudioActions.ts:272-276`, hiển thị tại `src/app/features/image-gen/components/ImageGenStudio.tsx:122`). Bổ sung 1 dòng mapping `40mb` ➔ `t("studioRefFileTooLarge")` (`src/lib/utils/translations/vi.ts:606`, `src/lib/utils/translations/en.ts:594`) trong `classifyStudioError` (`src/lib/features/image-gen/studioHelpers.ts:11-46`) bảo đảm người dùng tiếng Việt/Anh không thấy chuỗi tiếng Anh thô khi ảnh vượt 40 MB, mà không cần sửa `src/app/features/image-gen/components/hooks/useImageStudioActions.ts` (`324 <= 350` dòng, `TC-13`) hay file dịch.

#### 6.2 `requestImageVariation`, MIME Normalization & 40MB Bilingual Error (`src/lib/features/image-gen/studioHelpers.ts`)

```ts
// Import đơn 85 ký tự (<= 100 printWidth, không wrap dòng)
import { STUDIO_REF_IMAGE_MAX_BYTES } from "@/lib/features/files/uploadPresentation";

// Trong classifyStudioError (thêm 1 dòng 77 ký tự trước dòng return fallback):
if (lower.includes("40mb")) return { message: t("studioRefFileTooLarge") };

const VARIATION_MIME_EXT = {
  "image/png": "png",
  "image/jpeg": "jpg",
  "image/webp": "webp",
  "image/gif": "gif",
} as const;

function normalizeVariationMime(raw: string): keyof typeof VARIATION_MIME_EXT {
  const base = raw.split(";")[0]?.trim().toLowerCase() || "";
  if (base === "image/jpg" || base === "image/pjpeg") return "image/jpeg";
  if (base === "image/x-png") return "image/png";
  if (Object.hasOwn(VARIATION_MIME_EXT, base)) return base as keyof typeof VARIATION_MIME_EXT;
  return "image/png";
}

export async function requestImageVariation(params: {
  imageUrl: string;
  originalPrompt: string;
  conversationId: string;
  model: string;
  aspectRatio: string;
}): Promise<{ success?: boolean; [key: string]: unknown }> {
  const response = await fetch(params.imageUrl);
  if (!response.ok) throw new Error("Failed to fetch source image");
  const blob = await response.blob();
  if (blob.size <= 0) throw new Error("Failed to fetch source image");
  if (blob.size > STUDIO_REF_IMAGE_MAX_BYTES) {
    throw new ReferenceImageUploadError("Reference image exceeds 40MB limit");
  }
  const mime = normalizeVariationMime(blob.type || response.headers.get("content-type") || "");
  const file = new File([blob], `variation.${VARIATION_MIME_EXT[mime]}`, { type: mime });
  const refPaths = await uploadReferenceImages([file], params.conversationId, "Variation failed");
  const key = readStoredApiKey("vikini-gemini-key");
  const variationModel = params.model.includes("gemini-3")
    ? params.model
    : "gemini-3.1-flash-image";
  return postGenerateImageRequest(
    {
      prompt: buildVariationPrompt(params.originalPrompt),
      conversationId: params.conversationId,
      options: {
        model: variationModel,
        aspectRatio: params.aspectRatio,
        referenceImagePaths: refPaths,
      },
    },
    key,
    "Variation failed"
  );
}
```
