### 3. Assumptions, Blast-Radius & Cross-Task Dependencies

#### Các giả định đã xác minh bằng mã nguồn (`[SRC]`)

1. **Admin UI tương thích 100% với pagination mới & cột tường minh**: `src/app/admin/components/UserManager.tsx:75-78` gọi `fetch("/api/admin/users")` không truyền query params, đọc `(json.data || json).users || []` và lọc client-side trên mảng này (`src/app/admin/components/UserManager.tsx:89-101`), còn `src/app/admin/components/UserDetailModal.tsx:8-14` chỉ dùng đúng 5 cột `id, email, rank, is_blocked, created_at`. Do đó `GET /api/admin/users` giữ mặc định `limit = 1000` (tránh ẩn user 201..1000 trước khi Wave 2B thêm UI phân trang), chọn tường minh 5 cột, hỗ trợ `?limit=1..1000&offset>=0` và trả thêm `data.pagination = { total, limit, offset, hasMore }`.
2. **Redis GEM cache lưu theo từng user**: `src/lib/core/cache.ts:33` dùng key `cache:gems:${userId}` (`TTL = 300s`, `src/lib/core/cache.ts:39`) và `src/lib/features/gems/gems.ts:227-328` lưu cả premade + user gems vào key này. Xóa cache premade gem toàn hệ thống dùng non-blocking `redis.scan(cursor, { match: "cache:gems:*", count: 100 })` + `redis.del(...keys)` có giới hạn vòng lặp (`MAX_SCAN_ITERATIONS = 50`) giữ hot-path đọc `getCachedGems()` ở đúng 1 RTT.
3. **`exceljs` `workbook.xlsx.load()` nhận `ArrayBuffer` hợp lệ theo `.d.ts` gốc**: `exceljs` v4.4.0 khai báo `declare interface Buffer extends ArrayBuffer {}` và thực tế runtime gọi `JSZip.loadAsync(buffer)` chấp nhận trực tiếp `ArrayBuffer` (khớp `new Uint8Array(bytes).buffer`), loại bỏ hoàn toàn `as any` & `eslint-disable` tại `src/lib/features/files/documentParsers.ts:113-114`.
4. **Hành vi `chatStreamCore.test.ts` với `projectId: undefined`**: `src/app/api/chat-stream/chatStreamCore.test.ts:227-260` mock `conversation: { id: "conv-1", gemId: null }` không có `projectId` (`undefined`) và vẫn kỳ vọng `buildRAGContext` được gọi. Vì vậy `buildRAGContext(..., { projectId })` chỉ bỏ qua `getConversationProjectId()` khi `options.projectId !== undefined` (`null` => trả `emptyContext` ngay; `string` => dùng thẳng; `undefined` => truy vấn DB như cũ). Tương tự cho `preloadedGemId` và `preloadedPersonaId`.
5. **Bảo toàn `TC-03A` (`corrupted_remote`) & thứ tự CAS của `storyPersistence.server.ts`**: `src/lib/features/novelcrafter/storyPersistence.server.ts:171-178` phải tiếp tục gọi `decryptText(existingRow.content)` VÀ `JSON.parse(decryptedExisting)` (kiểm tra object hợp lệ) để phát hiện cả ciphertext lẫn JSON bị hỏng (trả 409 `DESTRUCTIVE_SAVE_REJECTED` với `reason: "corrupted_remote"`). Khi `Number.isFinite(existingMeta?.contentChars) && existingMeta.contentChars >= 0`, chỉ bỏ qua bước `sanitizeStoryState()` tốn kém trên bản ghi cũ. Việc dọn duplicate `rows.slice(1)` chỉ thực thi **sau khi** CAS `.update()` thành công (sau `src/lib/features/novelcrafter/storyPersistence.server.ts:312`).
6. **`batchGenQuota.ts` giữ export `getRedis`**: `src/app/api/batch-gen-quota/route.ts` import `getRedis` từ `@/lib/core/batchGenQuota`. Giữ `export function getRedis(): Redis | null { return getSharedRedis(); }` đảm bảo 0 breaking change cho route và `batch-gen-quota/route.test.ts`.
7. **Không dùng `docs/plans/...` làm dẫn chứng dòng**: Mọi số dòng dưới đây là số dòng thực tế của mã nguồn hiện tại ngày 2026-11-21.

#### Adversarial Timelines (4 Trục Kịch Bản Xấu Nhất)

1. **Trục 1 — Concurrency (Đa luồng đồng thời)**:
   - _Kịch bản_: Hai stream NovelCrafter của cùng user chạy song song ở sát ngưỡng `daily_message_limit` (`count = limit - 1`). Stream #1 phát token đầu và gọi `incrementDailyMessageCount`.

   - _Kịch bản 2_: Hai tab cùng lưu `story_state` đồng thời tạo ra 2 row trùng trong `messages`.
   - _Bảo vệ_: `GET` (`getStoryState`) tuyệt đối read-only và chọn row thắng theo `meta.version DESC` (không phụ thuộc `created_at`), đảm bảo không bao giờ xóa nhầm bản mới hơn; `saveStoryState` kiểm tra stale version, destructive drop, và CAS `.update()` — chỉ dọn duplicate `rows.slice(1)` **sau khi** CAS `.update()` thành công và `!existingCorrupted` (request bị 400/409 thực thi 0 lệnh `.delete()`).
2. **Trục 2 — TOCTOU (Time-of-Check to Time-of-Use)**:
   - _Kịch bản_: User gửi `PATCH /api/conversations` với `{ id, title: "OK", gemId: "<victim-private-gem>" }`, `DELETE /api/projects/<proj-A>/knowledge?documentId=<doc-of-proj-B>`, hoặc gửi raw base64 + `imageMimeType: "image/svg+xml"` / `DATA:IMAGE/SVG+XML;base64,...` vào `/api/edit-image-multi` & `/api/edit-image`.
   - _Bảo vệ_: `updateConversation()` chạy toàn bộ `assertGemAccessible` / `assertPersonaAccessible` / `assertProjectOwned` / `assertModelAllowedForUser` xong xuôi TRƯỚC lệnh `.update()` duy nhất (0 ghi bán phần); `deleteDocument()` gắn `.eq("project_id", projectId).eq("user_id", userId)` nguyên tử ngay trong mệnh đề `DELETE`; cả `ssrfGuard.server.ts`, `edit-image-multi/route.ts`, và `edit-image/route.ts` dùng chung `ALLOWED_IMAGE_MIME_TYPES` (case-insensitive) cho cả `imageMimeType` lẫn tiền tố `data:`.
3. **Trục 3 — Mid-stream / Cleanup Failure**:
   - _Kịch bản_: Client ngắt kết nối giữa chừng trên `novelcrafterStreamRunner`, hoặc `fileService.server.ts` bị `storage.upload` reject / DB `insert` lỗi sau khi `uploadToGemini` đã xong, hoặc `chatStreamCore.ts` bị `getUserLimits` reject (403/503), hoặc `gallery/[id]` xóa DB lỗi.
   - _Bảo vệ_: `ReadableStream.cancel()` kích hoạt `streamAc.abort()` dừng provider và `safeEnqueue()` không ném lỗi controller closed, `finally` luôn gọi `onStreamComplete()`; `fileService.server.ts` dùng `Promise.allSettled` để luôn thu hồi `gemini.name` (và `storagePath` nếu DB insert lỗi) kể cả khi `storage.upload` reject; `chatStreamCore.ts` chạy `getUserLimits` xong trước `loadOrCreateConversation` nên không tạo bản ghi `conversations` mồ côi; `gallery/[id]` xóa DB trước Storage nên DB lỗi không bao giờ tạo record mồ côi trỏ tới ảnh đã mất.
4. **Trục 4 — Serverless Constraints (Cold Start, Stateless Instances, Timeouts)**:
   - _Kịch bản_: Các route chạy trên Vercel Serverless nhiều instance độc lập không chia sẻ bộ nhớ RAM; `cleanupExpiredFiles` gặp DB outage hoặc worker không có `GEMINI_API_KEY` cho batch không chứa file Gemini; `admin/gems` đổi premade gem trên instance A trong khi user đọc trên instance B.
