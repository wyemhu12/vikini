     1.      2. Kiểm tra trống cổng (`assertPortAvailable` dùng `listen({ host, port, exclusive: true })`) trước khi khởi động `next dev` (chặn race condition đọc nhầm server cũ).
     3. Snapshot byte-exact `next-env.d.ts` trước khi bật server và khôi phục chính xác bằng `fs.writeFileSync` trong `finally` **chỉ khi tệp thực sự thay đổi** (tuyệt đối không chạy lệnh git mutating).
     4. Thăm dò sẵn sàng HTTP có giới hạn (`--ready-timeout-ms`, mặc định `60_000ms`, nhận watchdog `AbortSignal`) và fail sớm ngay nếu `next dev` thoát lỗi lúc khởi động.
     5. Watchdog tổng cứng (`--timeout-ms`, mặc định `120_000ms`) + xử lý tín hiệu `SIGINT`/`SIGTERM`, tiêu diệt triệt để toàn bộ cây tiến trình (`C:\Windows\System32\taskkill.exe /F /T /PID <pid>` trên Windows; `process.kill(-pid, "SIGKILL")` trên POSIX nhờ `detached: true`) cho **cả** `qaChild` (spawn với `detached: process.platform !== "win32"`, `stdio: ["ignore", "inherit", "inherit"]`) lẫn `serverChild` trong `cleanupOnce()` idempotent, dọn `clearTimeout(watchdogTimer)` và gỡ listener `SIGINT`/`SIGTERM` trong `finally`, khôi phục `next-env.d.ts`, và **chỉ gọi `process.exit(code)` trong `runCli()`** (không bao giờ gọi trong `runVisualQa()` để an toàn với worker Vitest).
     6.
